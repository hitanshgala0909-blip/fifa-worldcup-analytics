## 3. Feature Engineering — Complete Specification

### 3A. V1 Feature Vector (8 features — pipeline only, not for production use)

```
[elo_diff, exp_home_win, gf_diff5, ga_diff5, wins_diff5, ppm_diff5, tournament_code, neutral_int]
```

### 3B. V2 Feature Vector (17 features — PRODUCTION, used in calibration file)

Built inside `predict_match_calibrated()` in `wc2026_upset_calibration.py`:

```python
feat = [
    dr,                          # ELO difference: elo_a - elo_b
    exp_h,                       # ELO-implied win probability for team_a
    fa["gf5"]   - fb["gf5"],     # Goals scored diff (last 5 matches)
    fa["ga5"]   - fb["ga5"],     # Goals conceded diff (last 5 matches)
    fa["wins5"] - fb["wins5"],   # Wins diff (last 5 matches)
    fa["ppm5"]  - fb["ppm5"],    # Points per match diff (last 5 matches)
    tournament_code,             # 4 = World Cup
    int(not neutral),            # 1 if home advantage applies (always 0 for WC)
    # Squad strength differentials (team_a - team_b):
    sq_diff["avg_index"],        # Average player overall index
    sq_diff["top3_index"],       # Average index of top 3 players
    sq_diff["avg_form"],         # Average squad form score
    sq_diff["avg_fitness"],      # Average squad fitness
    sq_diff["avg_rating"],       # Average squad match rating
    sq_diff["avg_xg90"],         # Average xG per 90 minutes
    sq_diff["avg_xa90"],         # Average xA per 90 minutes
    sq_diff["wc_exp"],           # World Cup experience score
    sq_diff["avg_caps"],         # Average international caps
]
```

All 17 features are scaled via `scaler_match_v2.pkl` before calling `lr_v2.predict_proba()`.

### 3C. Rolling Form Computation

Form features are computed by `get_form()` in the calibration file:
- Takes the **last 5 completed matches** for a team from `results.csv`
- Returns `{gf5, ga5, wins5, ppm5}`
- Default fallback if no history: `{gf5: 1.3, ga5: 1.1, wins5: 2.0, ppm5: 1.3}`

> **Production action required:** Pre-compute and cache `form_cache` as a JSON or CSV file at pipeline run time. Do not rebuild it from `results.csv` on every API startup.

## 4. The Calibration Layer

Defined as `calibrate_wc_probs(p_fav, p_draw, p_und, elo_gap)` in `wc2026_upset_calibration.py`.

This is not optional — it is what makes the predictions realistic.

**How it works:**

1. Look up a historical WC prior based on the ELO gap between the two teams:

| ELO Gap | Fav prior | Draw prior | Underdog prior | Model trust (alpha) |
|---|---|---|---|---|
| 0–50 | 33% | 28% | 39% | 35% |
| 50–100 | 47% | 23% | 30% | 45% |
| 100–150 | 43% | 23% | 34% | 55% |
| 150–200 | 44% | 22% | 34% | 55% |
| 200–300 | 56% | 16% | 28% | 65% |
| 300+ | 57% | 13% | 30% | 70% |

2. Blend: `p_calibrated = alpha × p_model + (1 - alpha) × p_prior`
3. Enforce hard floors and caps:
   - **Floor:** No team below 10% win probability
   - **Cap:** No team above 80% win probability
4. Renormalise so all three probabilities sum to exactly 1.0

**Example outputs after calibration:**
- Spain vs Curacao: 78% / 12% / 10%
- Argentina vs Saudi Arabia: 64% / 18% / 18%

## 7. Tournament Simulation Architecture

The simulation runs in `wc2026_upset_calibration.py`, Section 4.

**Key functions:**

| Function | Purpose |
|---|---|
| `simulate_tournament_calibrated(group_members, rng)` | Run one full 48-team tournament. Returns `{team: stage_reached}` |
| `sim_group_stage(teams, rng)` | Simulate one 4-team round-robin using calibrated probabilities |
| `sim_ko_match(ta, tb, rng)` | Simulate one knockout match. Draws go to penalties (near 50/50 with tiny ELO tilt) |

**Format:** 10,000 Monte Carlo runs. Each run plays ~80 matches. Outputs win/reach percentages for all 48 teams.

**Bracket structure:** The official FIFA 2026 R32 bracket is hard-coded as `R32_BRACKET`, `R16_BRACKET`, `QF_BRACKET`, `SF_BRACKET`, `FINAL_BRACKET` in the calibration file. The simulation uses this exact seeding structure.

**Qualification logic:**
- Top 2 from each of 12 groups = 24 teams
- Best 8 third-place teams (by ELO) = 8 more teams
- Total R32 field = 32 teams

## 9. Production-Readiness Changes Required

These are targeted changes only. **Do not retrain or modify any model.**

### Critical (must fix before deployment)

| Issue | Location | Fix |
|---|---|---|
| Form is rebuilt from raw CSV at startup | `wc2026_upset_calibration.py` line 107 | Run `form_cache = {t: get_form(t) for t in WC26_TEAMS}` once after pipeline runs and save as `data/form_cache.json`. Load the JSON in the API. |
| Hard-coded absolute paths | Both files | Replace `BASE_DIR`, `DATA_DIR`, `MODEL_DIR` with `os.environ.get("WC2026_DATA_DIR", "data")` etc. |
| XLSX loaded on every calibration run | Line 110–114 of calibration file | Save `group_members` as `data/group_members.json` after the pipeline runs. Load the JSON in the API instead. |
| No input validation on team names | `predict_match_calibrated()` | Add a guard: `if team not in WC26_TEAMS: raise ValueError(f"Unknown team: {team}")` |
| Model version confusion | Both files reference different model files | Document clearly: the API must load `lr_match_v2.pkl` + `scaler_match_v2.pkl`, never `best_match_model.pkl` + `scaler_match.pkl` |

### Recommended (improve reliability)

| Issue | Fix |
|---|---|

## 12. What the Backend Must NOT Do

- **Do not retrain any model.** All `.pkl` files are the source of truth.
- **Do not call `compute_elo()` or `compute_rolling_form()`** at API startup. These are offline pipeline steps.
- **Do not read `results.csv` or the XLSX at API request time.** All data needed for inference should be pre-loaded from lightweight JSON/CSV files.
- **Do not use `best_match_model.pkl`** for production predictions. It may be RF or XGBoost depending on which scored highest — use `lr_match_v2.pkl` which is the model the calibration layer was specifically built and tuned around.
